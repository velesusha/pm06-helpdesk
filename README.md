# Практика ПМ.06 — система заявок ИТ-службы

Рабочее веб-приложение по 18 картам учебной практики. Исходный учебный проект и CSV созданы с нуля по заданию. Данные и имена тестовых сотрудников вымышленные.

## Быстрый запуск на этом компьютере

1. Откройте папку проекта и дважды нажмите **START.bat**.
2. Откройте **https://localhost:8443**. Сертификат создаётся локально при первом запуске. Он самоподписанный, поэтому браузер покажет предупреждение. Решение о доверии этому локальному сертификату принимает пользователь.
3. Войдите под `operator`, `engineer`, `engineer2` или `admin`. Общий учебный пароль: `Practice2026!`.
4. Для остановки сервера нажмите Ctrl+C в окне запуска.

`START.bat` загружает 8 учебных заявок при первом запуске. Повторные запуски не создают дубликатов. Для проверки первого импорта запустите **START-CLEAN.bat**: он использует отдельную, первоначально пустую базу `data/clean-demo`. После первого импорта она сохраняется. Для нового чистого стенда задайте другой пустой каталог через `HELPDESK_DATA`.

Локальный просмотр без сертификата: `powershell -File .\start.ps1 -Http`. Адрес **http://localhost:8096**. Для карты № 7 используйте HTTPS.

Скрипт ищет Python в `.venv`, затем в среде Codex на этом компьютере, затем команды `py` или `python`. На другом компьютере нужен Python 3.10+ и пакет `cryptography` для HTTPS. Установка: `python -m pip install cryptography`. Приложение слушает только локальный адрес 127.0.0.1.

## Возможности

- Вход, выход, хеширование паролей PBKDF2 SHA-256, защищённые сессии и CSRF-токены.
- Оператор: создание, назначение, импорт, выгрузка, закрытие решённых заявок.
- Исполнитель: просмотр только назначенных ему заявок, начало работы и отметка решения.
- Администратор: все заявки, учётные записи, категории, журнал действий.
- Список и карточка, поиск по теме или source_id, фильтры по статусу, категории и кабинету.
- Статусы: Новая → В работе → Решена → Закрыта. Решённую заявку можно вернуть в работу.
- Импорт CSV UTF-8: 8 новых записей из 10 строк; повторный импорт добавляет 0.
- Правила приоритета с пояснением в карточке, история изменения статусов и назначения.
- Выгрузка контрольных данных, резервное копирование и восстановление отдельной демонстрационной БД.

## Важное для сдачи

**В исходном задании указан SQL Server.** Для немедленного запуска здесь используется SQLite. Для SQL Server подготовлены адаптер, схема и команды SSMS. Подключение и операции с `.bak` в этой среде не проверены: SQL Server и ODBC-драйвер здесь отсутствуют. SQLite-копии имеют расширение `.db` и не выдаются за SQL Server `.bak`.

Отчёт находится в `reports/practice.html`, исходный текст — в `docs/report.md`. В нём есть ТЗ, описание БД, материалы к 18 картам, ответы, матрица доступа, руководство, памятка и сценарий защиты. Заполните свои ФИО, курс, группу, фактические даты и сведения руководителя. Оценки, подписи и факт инструктажа подтверждает преподаватель. Выписка из реестра и реквизиты протокола испытаний должны быть получены у преподавателя.

Автоматические результаты относятся к SQLite. Для окончательной сдачи повторите проверки и восстановление с входом не более чем за 30 минут на SQL Server; добавьте собственные скриншоты и реальные даты. Три дефекта из задания разобраны как учебные примеры в `exercises/defect_examples.py`; приложение поставляется с исправленным поведением.

## Подключение SQL Server

1. Установите SQL Server Developer или Express, SSMS и Microsoft ODBC Driver 18 for SQL Server на учебном стенде.
2. В SSMS создайте пустую БД: `CREATE DATABASE Pm06Helpdesk;`.
3. В выбранной среде Python установите `pyodbc`: `python -m pip install pyodbc`.
4. В PowerShell задайте строку подключения с проверяемым сертификатом сервера:

```powershell
$env:HELPDESK_SQLSERVER = 'DRIVER={ODBC Driver 18 for SQL Server};SERVER=localhost\SQLEXPRESS;DATABASE=Pm06Helpdesk;Trusted_Connection=yes;Encrypt=yes;TrustServerCertificate=no;'
.\start.ps1
```

Имя SQL Server и настройки TLS согласуйте с преподавателем. Пароли SQL-аутентификации храните в переменной окружения, не в коде. При первом запуске `app.py` создаст таблицы из `sql/schema_sqlserver.sql` и учебные учётные записи. Сервер SQL должен иметь сертификат, которому доверяет клиент, либо администратор должен настроить TLS учебного стенда.

Для полной копии и восстановления используйте `sql/backup_restore.sql`. Укажите доступные SQL Server пути, получите логические имена через `RESTORE FILELISTONLY` и восстановите в **новую** БД `Pm06Helpdesk_Restored`. В копии строки подключения замените имя базы и запустите второй экземпляр приложения с другим портом. Сравните число заявок, id/source_id, статусы и assignee_id с контрольной выгрузкой.

## Резервная копия демонстрационного режима

Команды выполняются выбранным интерпретатором Python из папки проекта:

```powershell
python maintenance.py backup
python maintenance.py restore --file data/backups/ИМЯ_КОПИИ.db --target-dir data/restored-demo
$env:HELPDESK_DATA = "$PWD\data\restored-demo"
python app.py --port 8444
```

Каталог назначения не должен содержать базу: существующие базы не перезаписываются. Восстановленные сессии очищаются; нужно войти заново. Рядом с копией сохраняются контрольный CSV, число записей, версия и SHA-256. Для сравнения:

```powershell
python maintenance.py compare data/helpdesk.db data/restored-demo/helpdesk.db
```

## Проверки и структура

```powershell
python -m unittest discover -s tests -v
python tools/verify.py
```

`app.py` — HTTP API и HTTPS, доступ, импорт, две СУБД; `web/` — интерфейс; `maintenance.py` — копирование SQLite; `sql/` — SQL Server; `tests/` — автоматические проверки; `reports/verification.json` — фактический протокол; `reports/screenshots/` — снимки выполненных браузерных проверок; `docs/` — материалы для отчёта.

Для нового стенда не переносите рабочую базу, журналы, сессии и закрытый ключ из `data/certs`. Сертификат нового компьютера создаётся заново. Учебные учётные записи предназначены для локальной демонстрации.
